01Hume Tools Overview＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

1.1 Introduction

Hume tools

The Hume tools that we encounter on a daily basis are Curry, aka the Knowledge Graph Editor (KGE), and Tasky, the job assignment interface.

Curry is the ultimate Knowledge Graph Editor. It allows us to curate data and override incorrect values originating in other data graphs.

The home page for Curry is:

https://hume.google.com/edit

Assignment of jobs and job queues is managed in a job management user interface called Tasky. From Tasky, you start work on new tasks and resume work on tasks that were temporarily put on hold.

The home page for Tasky is:

https://hume.google.com/Tasky/assignments

Browser requirement: When working with these tools, use Google Chrome, a stable non-beta release. A Beta version can be recognized by “dev” at the end of the version number. You can check your Chrome version at chrome://chrome/.

02Topics, Types, Properties & Values＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

2.1 Topics

Topics are assigned machine IDs (MIDs) that start with /m/, /g/ or /x/.

/m/ IDs come from the Freebase graph, the forerunner of Curry.

The origins of /g/ IDs are unknown.

/x/ entities appear in experimental jobs.

We only do edits on /m/ and /g/ topics.

Unreconciled Objects (URO)

Unreconciled Objects (URO) are entities that are not reconciled to any topic and are not confirmed as new topics.

UROs have a colored banner with “Unreconciled Object (URO)” and a type of “Not yet reconciled.”

We do not edit UROs, but we can merge them with topics.

Geo topics

Geo topics are managed by the Geo team. They have a colored banner with a “Maintained by Geo (Geo Curation Guideline)” note.

We edit them according to the Geo Curation Guideline.

2.2 Types

Common types describe topics, e.g. animal owners, people, structures, etc. Common types are found in KG, Hogwild, Geo schema, etc.

We mostly curate types from the KG schema, except for /base and /user types.

Compound Value Types (CVT)

Compound value types (CVTs) express relationships between topics such as ownerships, memberships, marriages, and tenures.

CVTs have separate pages that are accessed by clicking on “view.” CVTs are usually nameless, with a MID as their only identifier.

2.3 Properties

Properties contain values pertinent to the type.

Properties with many values will show the top 10 by default. To see all the properties, click “more.” To arrange all properties alphabetically, click “sort.” In CVTs, click on property headers to sort.

Special property indicators

Locked properties

Locked properties are disabled for Hume editing. They are marked with a lock sign.

High fan-out properties

High fan-out properties have a lot of values. They are marked with a carrot sign with three horizontal dots.

Sensitive properties

Sensitive properties require double-checking before editing. They are marked with a triangle sign containing an exclamation mark. Pay attention to the message they contain.

Bare properties

Bare properties can be curated without asserting a type, e.g. /type/object/name.

Zombie properties

Zombie properties must have a type asserted. Properties become zombies when their type was removed, but their values were not.

2.4 Values

Values that you see in properties are topics, text (letters or numerals), and flags (Has value or No Value).

Behind each value is a process (team) that asserted it. You can find out each value's provenance and assertion sources.

03Provenance & Assertion Sources＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

3.1 Provenance

Provenance shows what process added the value to the graph.

Check provenance by clicking on the three-dot menu on the top-right-hand side of any type. When selected, each value will show the process and a “show sources” link.

3.2 Assertion sources

Data sources contain values that are asserted to topics.

To access assertion sources, click the “show sources” link.

Non-Hume provenances point to partners' assertion sources.

Hume-Curry provenance points to our contributions (CIDs), where values were added.

Some provenances cannot be touched by Hume. If bad data comes from such assertion sources, it is reported to partners to be fixed on their end.

05Search in Curry＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

5.1 Basic search

You can search for information on Hume in the same way you would on many other websites: by entering keywords in a search box.

The search box has an autocomplete feature. As you type, it suggests relevant matches from the millions of topics in the Knowledge Graph.

It initially displays 20 search suggestions. You can use the scrollbar to view those at the bottom. When you scroll to the bottom, it automatically loads more suggestions.

If you hover your mouse over any suggested result in Hume, a flyout appears containing relevant information about the topic. All types found on the topic are listed at the bottom of the flyout. The list of types is collapsed by default and expands when you hover over it.

You can open a topic by clicking on the suggestion. You can open a topic from the dropdown in a new tab by pressing CMD+Click on Apple systems or CTRL+Click on Windows/Linux systems.

5.2 Search landing page

You can access the Hume search landing page by doing any of the following:

Going to https://hume.google.com/graph/search

Opening any Hume page and clicking “advanced,” found directly beside the search box at the top of the page.

Entering text in the search box and pressing ENTER.

5.3 Using filters

You can search for musical artists named Taylor Swift using:

Taylor Swift t:/music/artist

Taylor Swift type:/music/artist

Important note: If your search does not return results that you know exist, search other contributions or use advanced search, especially when searching for duplicates.

06Filtering & Advanced Search＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

6.1 Filtering by property

The advanced search allows you to filter search results by type and also by property.

Example: You are looking for John Black, a politician who died on August 29, 1854.

Looking for topics named John Black that are politicians and deceased persons may yield over a dozen results.

By selecting “Exact match,” the search shows only results for persons whose exact name is John Black. This reduces the number of results to three candidates in the example.

Please remember that the “Exact Match” search is case sensitive. A search with exact match for john black, without capital letters, will trigger no result in this example.

To determine which of the three candidates has the matching date of death, you can either open each candidate or use a property constraint to filter the search results using the known date of death.

Only one result comes up in the example. Opening it allows you to confirm that it is the right candidate.

Regular date formats

The standard date formats are:

yyyy-mm-dd

yyyy-mm

yyyy

If the date is August 29, 1854, it should be entered as 1854-08-29.

If the digits of the day or month are less than two digits, add a leading zero.

January 1923: 1923-01, not 1923-1.

3 June 1960: 1960-06-03, not 1960-6-3.

The type and property constraints are powered by Suggest. If you do not know the exact name of the type or property, start typing the words you would commonly use or the words given in the instructions. You will see suggestions for types and a flyout window with a definition of the type.

Alternatively, open a topic with the correct type and look up the name of the property.

07Reliable & Unreliable Sources＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

7.1 Sources and research

The basic and simplest task that every contributor must know how to do well is online research. Whether you are a beginner or an advanced contributor, online research skills are essential.

This section discusses some pointers and specific steps for finding valid online sources. Understanding sources and how to limit the extent of external search is also very important.

7.2 Reliable and unreliable sources

There are several types of information sources available for us to use, but we must be cautious when choosing them. Some sources are not reliable because the information they contain cannot be trusted.

Determining whether a source is reliable or official can be tricky, but there are ways to assess it.

General user-created sources are very common, and these are often the ones we want to avoid. However, some user-populated sources, such as Wikipedia and IMDb, go through verification processes, and their data is often correct, although it may sometimes be incorrect or outdated.

Unreliable sources

Sources that we generally want to avoid will often contain the following:

A lot of advertisements surrounding the data.

Information reproduced exactly as it appears on Wikipedia or other websites.

Poor website structure.

An unfamiliar or off-topic domain name.

We also usually consider the following unreliable:

Online forums. Example: Reddit.

Websites with user-generated content, excluding Wikipedia. Example: The Movie Database (TMDb).

Websites with obvious substandard quality, such as poorly created, unpopular, or hobby-maintained sites.

Aggregators. Example: Digg.

Popular websites that are not considered sources within our projects, including Netflix, eHow, Yahoo Answers, WikiAnswers, WikiHow, and Wikia, among others.

Fan-made sites.

Sources that use machine-translated content.

Reliable sources

Official or reliable sources will often contain:

Little to no advertising.

Unique content.

Well-structured data with several pictures.

A topic-related domain name.

Additional types of sources that can be considered official or trustworthy include news, financial, magazine, or official sports websites, such as The New York Times, The Herald News, CNN, Forbes, Time, Newsweek, NFL.com, NBA.com, and ESPN.com, among others.

Official websites are also important sources.

Pointers to assess whether a source is reliable

When you find a website and try to assess its reliability, consider the following.

Check the URL: One of the most obvious ways to determine whether a website is valid is to examine its URL. Domains such as .gov and .edu are generally very reliable sources.

About Us and Contact Us sections: Find out more about the entity that owns or manages the website. Is it an institution or an individual? If the website does not contain these details, it may not be reliable.

Real-world entities: Websites such as mcdonalds.com and nasdaq.com are considered reliable because they represent real-world entities. This also applies to local websites within your region, e.g. Inquirer.net, which is owned and managed by a newspaper organization in the Philippines.

Who wrote what? When dealing with articles, check who the author is and the purpose of the article. Is it an academic publication, official government information, data, or gossip?

Freshness: Whenever you enter a fact in Hume, ensure that the information is up to date. Always check the freshness of sources, especially for time-sensitive data, such as the current population of a location.

Sources: Find out where and when the website acquired its data. For example, does it link to other online sources, as in the References section of a Wikipedia topic?

Official website or fan site? For music artists or celebrities, websites may look official but actually be fan-made. A mention or disclaimer may confirm that a site is not official. Fan sites are not considered reliable sources.

These are pointers, not universal rules that work in every situation.

7.3 Inaccurate or contradicting sources

No source is 100% reliable. Even Wikipedia or IMDb may contain mistakes. Finding a name within a reliable source does not automatically mean it is correct.

In rare cases when two different values for the same property appear in a Wikipedia article, or in the article and its infobox, such as two different places of birth, look for external sources to confirm which value is more correct. Otherwise, leave the property blank.

Do not add information provided in the Wikipedia Categories section at the bottom of an article if that information is not confirmed by the article or external sources.

When the data presented in a reliable source uses phrases such as “reportedly,” “allegedly,” “apparently,” or “supposedly,” pay special attention to the context. These phrases may indicate that the data is not factually established.

We want to get as close to 100% accuracy as possible. When you still have doubts about a value after research, leave the property blank.

Evaluate each source scenario.

10Editing Topics, Types, Properties & Values＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

Important note: All graph edits should be done within tasks according to the job scope specified in the job GL.

10.1 Creating new topics

You can create new topics either from another topic or from a schema type by clicking [+] New Topics.

In the pop-up window:

Add the topic's name.

Select the language.

Start typing the type to prompt autocomplete.

If you create from the type directly, the type will be preselected.

Press OK to save.

You can also create a new topic directly from a property by typing a topic name and selecting “create new.”

Important note: New topics created in In_Progress / In_Review contributions do not appear in the graph until the contribution is reviewed and submitted. Opening the new topic links while in this state may return an error.

10.2 Asserting and removing types

You can assert a type to a topic by clicking [+] Add type.

In the pop-up window, start typing the type you want to assert to prompt autocomplete. Press OK when done.

You can remove a type by clicking the three-dot menu in the top-right-hand corner of a type.

You will only be allowed to remove a type if all its values are removed, with the exception of /common/topic, which does not require removing all values but asks for confirmation before proceeding.

To remove a CVT from a topic (unlink the CVT from the topic), click “remove” in front of the CVT.

To delete a CVT from the graph, go to the CVT page and remove all values and types from there. The entity will eventually get cleaned up.

Closed Set type: A Closed Set type is a type whose instances are already represented in KG. When a value is added to or removed from a Closed Set type in a contribution, a linter error will be triggered. Contributors should contact CLs in such cases.

10.3 Editing properties

To edit a property, click the Edit button next to it.

A blank field shows the expected type of topics that are added or created in that property, e.g. /film/film.

Click “x” to clear values or an arrow to undo clearing.

To add an existing topic, start typing its name and select it from the dropdown list, or enter the MID.

To create a new topic, choose the “create new” option from the dropdown. New topics are marked NEW before you save the edit.

Editing properties in CVTs is done in the same manner by filling out each field according to the job GL.

Important notes:

Locked and sensitive properties need CL approval before editing. If editing locked properties is allowed in your job, the GL will explain the process of handing off such tasks to Locked properties badge.

If you edit a CVT from its page, the curated values shown in the contribution cart may not appear on the topics. This is not a concern. When the edits are visible in the contribution cart, they will be processed correctly.

10.4 Literal values

Adding, changing, or removing literal values does not affect any topic other than the one being updated.

Dates

When adding or editing date values, suggestions appear as you type in a date field.

Display formats are:

yyyy-mm-dd

yyyy-mm

yyyy

The year 234 BC can be entered as-is, and the number value -0233 will be suggested by the tool.

BC date examples:

1 BCE = 0000

2 BCE = -0001

Datetime

When events are curated with datetime values, use minute-level specificity where available, e.g. 2016-09-20T23:59:59Z, instead of just 2016-09-20.

For events, choose the time in UTC (offset by Z in the dropdown) to avoid time conversion problems.

Important note: The day starts at T00:00:00Z and ends at T23:59:59Z.

Text-based values

Keys and Property IDs are unique values that link to external sources, e.g. Wikipedia and IMDb, and are listed in the /type/object/key property.

Keys are asserted from data sources or manually. All keys are appended to namespaces.

The film Gone With The Wind has the key tt0031381 in the /authority/imdb/title namespace.

Keys will eventually migrate to dedicated ID properties.

Names have language codes beside them.

When editing names, languages that are already asserted or used are disabled in the language dropdown. If you want to change a name for a language, you need to remove the existing value before adding a new one.

Important notes:

Wikipedia topic names can be edited by moving the Wikipedia name to alias or completely removing it if invalid.

Do NOT edit or add names to Geo topics.

Descriptions

Descriptions can be autoloaded from outside sources or added manually.

If a topic has a Wikipedia description (blurb), there is no need to edit the description property at all.

Manually added descriptions should be grammatically correct, brief (1–2 sentences), and highlight what is known about the topic.

Important note: Do NOT edit descriptions written by processes other than Hume-Curry.

Numbers

Numbers sometimes follow specific units of measurement. An example is the Weight property in the Person type, which should always be in kilograms.

Be careful not to use the wrong unit for such properties. Like dates, suggestions appear as you type. Select the number you want to add from the dropdown.

10.5 Flags

Has value (HV) means the property has a value but the value is unknown.

Has no value (HNV) means the property has no value.

To flag a property, click the HV or HNV link.

To remove a flag, click the Remove link beside it.

Important notes:

We should not flag properties that are instances of All-has-value or when the schema manual or job GL does not ask for it.

There is no need to remove existing flags unless specifically stated.

11Standard Workflow in Tasky＋

Guide text below uses the definitions and wording from the provided Certification Hume User Guide.

The standard workflow includes Curation, Review, Audit, Revision, and Senior Review.

11.1 Curation (C)

Contributor 1 (Curator) curates the task according to the instructions and submits suggested edits for review.

11.2 Review (R)

Contributor 2 (Reviewer) reviews the edits.

If all edits are correct, the reviewer approves the contribution and the edits are written to the graph.

If some or all values are incorrect, the reviewer rejects the contribution and asks the curator to fix the errors.

11.3 Audit

An audit applies to a percentage of approved tasks.

Contributor 3 (Senior Reviewer) checks the edits. If the edits are correct, the senior reviewer approves the task. If not, the task follows the correction process.

11.4 Revision

Contributor 1 (Curator) receives the task back, makes the necessary edits, and resubmits it for review.

11.5 Senior Review (SR)

Contributor 3 (Senior Reviewer) checks the revised edits. The applicable review and correction process is followed.

Arrange these stages in the correct sequence:

Revision

Review

Curation

Senior Review

Audit, where applicable

Curation

Review

Audit, where applicable

Revision, if corrections are required

Senior Review of the revised work, following the applicable workflow

The precise path depends on the task's review and audit requirements.

Definition and required action

13Key Rules for Certification＋

Quick reference based on the Certification Hume User Guide.

Use the correct tool

Use Curry (Knowledge Graph Editor) to inspect topics and the graph; use Tasky to work on assigned tasks and submit contributions.

Follow task scope

All graph edits must be made within tasks and according to the job Guidelines (GL). Never work on a queue item outside Tasky.

Verify identity

Do not merge topics based on names alone. Check identifying details and follow the reconciliation process.

Check provenance

Inspect provenance and assertion sources before deciding how incorrect data can be corrected.

Choose reliable sources

Check ownership, authorship, freshness, references, and whether a site is official. Avoid fan sites and unreliable user-generated sources.

Do not guess

If credible sources conflict and research does not resolve the uncertainty, leave the property blank according to the applicable GL.

Respect property indicators

Locked and sensitive properties require special handling and may need approval or handoff. High fan-out properties need extra care.

Use correct flags

HV means a value exists but is unknown. HNV means the property has no value. Follow the schema manual and job GL.

Follow review workflow

Curation is followed by review; audit may apply. Incorrect work may return for revision and senior review.

Follow schema status

Use the deprecation status and job GL to determine whether curation belongs in the existing schema, both schemas, or the new schema.
